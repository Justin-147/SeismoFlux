- 日期：2026-07-30
- 唯一蓝图：`SEISMOFLUX_IMPLEMENTATION_HANDOFF.md`
- 协议：`stage4-kde-development-v1` / `0.4.3`
- 审计结论：`FAIL`，发现新的 foundational P0
- 真实开发目标读取：0
- 独立验证读取：0
- 锁定测试读取：0
- 唯一开发科学 attempt 消耗：0
- 当前决定：停止 whole-record/provenance 工程路线，保留科学问题与冻结评价门，改用更直接的实际置乱—重训—评分实验

## 1. 一句话结论

新入口能运行，但它没有真正把异常特征置乱后重新训练正式模型，所以其置乱分布、p 值和通过门没有
科学含义。继续给记录增加哈希或封条不能修复这个问题，当前未提交实现必须停止。

## 2. 独立审计发现的 foundational P0

### 2.1 置乱没有进入正式模型

`kde_dev_runner.py` 的纯合成路径把时间或空间 mapping 的平均位移压缩成一个 `marker`，再用该
`marker` 构造固定三点玩具数据并拟合。时间和空间 mapping 没有应用到实际 `B1/B2` 特征，也没有：

1. 重建完整训练和评估输入；
2. 重新拟合与 observed 路径相同的预处理器和模型；
3. 冻结预测后按同一目标和 600,000 平方公里报警面积重新评分。

因此 1,000 次时间置乱和 1,000 次空间置乱不是“异常信息被置乱后的正式预测效果”，不能用于判断
异常是否真的提供增量信息。

### 2.2 whole-run record 不能证明复本来源

记录行只保存 context、pool、mapping/draw 的摘要，没有保存可重算的实际 draw/mapping。validator
只重算 gate、复本数量和最外层摘要，没有重算
`replication index → context → pool → mapping → model value` 的完整关系。

独立纯合成攻击在重新计算最外层摘要后，以下篡改均被接受：

- 交换两条完整复本行；
- 同时修改时间行的 context、pool、mapping 和统计值；
- 修改 protocol、experiment 和 execution identity。

这说明该 record 只能检查自身格式，不能证明数值来自规定实验。

### 2.3 普通测试通过不能覆盖 P0

- runner 聚焦测试：`5 passed`
- 五个 Stage 4A 薄模块联合回归：`177 passed`
- Ruff、format、strict mypy、`git diff --check`：通过

这些只证明被测试的工程行为能够运行，不是预测效果证据，也不能使错误的置乱实验变得有效。

## 3. 通俗解释

原本要做的是：把异常报告的时间或位置真正打乱，重新训练一次模型，再看预测成绩是否下降。

当前程序做成了：只计算“平均移动了多远”，把这个数字交给一个三点玩具模型。它没有让真实异常特征
重新进入正式训练，因此相当于没有真正重考。给这张错误答卷加更多封条，不能让答案变正确。

## 4. 硬停止决定

立即执行以下边界：

- 不 code freeze 当前 one-shot 实现；
- 不提交或推送当前 runner 及其测试；
- 不打开真实开发目标、独立验证或锁定测试；
- 不消耗 `stage4-kde-development-v1-attempt-1`；
- 不再增加 whole-record、receipt、detached SHA 或自验证 provenance 补丁层；
- 保留已经通过的 75 km KDE 合法背景和 `0.4.3` 科学门，不改变折、窗口、面积、特征候选或通过阈值。

## 5. 科学优先的简化执行方案

### 5.1 不变的科学问题

仍只比较：

- `B0`：75 km KDE；
- `C0`：KDE + 观测覆盖控制；
- `B1`：KDE + 单期异常；
- `B2`：KDE + 动态异常。

仍固定三个滚动折、7/30/90 天、600,000 平方公里报警面积、2,000 次物理事件块 Bootstrap、
1,000 次时间置乱、1,000 次空间置乱，以及既有信息增益、严格召回、同时区间、`maxT` 和跨折/
跨区门。不得看成绩后改候选、折、面积、特征或阈值。

### 5.2 每个置乱复本必须真正做的事

每个时间或空间置乱复本必须使用同一条实际模型路径：

`冻结原始池 → 生成 mapping → 重建实际 B1/B2 特征 → 同样的预处理 → 重新拟合 → 冻结预测 →
同样的目标和面积评分`

正式执行必须直接调用已经公开的实际特征重建原语
`rebuild_time_placebo_features` / `rebuild_space_placebo_features`，并把重建结果送入与 observed 路径
相同的拟合和评分函数。只计算位移摘要、用玩具数据替代实际特征，或直接构造统计值，一律失败关闭。

### 5.3 证据边界简化

不再声称单个自验证 record 能独立证明全部来源。采用普通、可复现的研究证据链：

1. Git 冻结代码与精确依赖文件哈希；
2. 冻结输入 manifest 和既有单次 target-read ledger；
3. 结果文件保存运行身份、实际 draw/mapping、模型指标和 gate；
4. 独立复跑器从实际 draw/mapping 和冻结输入重算抽样复本；
5. SHA-256 只用于检查文件是否变化，不再被称为科学来源证明。

这降低的是工程复杂度，不降低未来信息隔离、单次读取、实际置乱、重训、固定面积比较和统计门。

## 6. 打开真实目标前的最近一步

先做一次仅限 manifest/schema 的 score-blind 预检，不读取 `data/processed` 真实字节和任何目标值：

1. 核对阶段 3 冻结特征表是否包含时间置乱重建所需的全部键；
2. 核对是否有冻结的 `issue × spatial stratum` 组支持空间置乱；
3. 核对 `B0/C0/B1/B2` 能否由同一实际表组装；
4. 核对三个滚动折、暴露、25 km 单元质量和 600,000 平方公里前缀所需字段；
5. 核对现有两个 rebuild 函数能否直接消费这些冻结 schema。

只有五项全部通过，才允许冻结一个最小实际 runner。若缺字段，只能回到阶段 3 输入构建修复，不能
猜字段、临时造数据或读取目标后补表。

## 7. 新的硬停止条件

出现任一情况即停止异常路线实现并保留 KDE：

- 现有冻结异常表不能支持实际时间/空间置乱；
- 需要读取目标后才能决定特征、分层、候选或重建规则；
- 简化 runner 又开始增加新的 provenance/receipt 层，而没有形成实际特征重建和重训；
- observed 与 placebo 没有经过同一拟合、预测冻结和评分路径；
- 唯一 Stage 4A attempt 失败或证据不足。

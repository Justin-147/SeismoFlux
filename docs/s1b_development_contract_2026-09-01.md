## 外行版

对每个要检验的5年历史阶段，先只在它前面的15年做三次“用早期预测后期”小考，
用小考选带宽、混合权重和收缩强度。小考答案至少要比正式阶段早30天成熟；每次起报又只能
看到24小时以前已发布的目录。这样后面的地震不能偷偷帮助前面选模型。

## 不可改变的因果边界

- 起报轴：每周四北京时间00:00；预测时长为7/30/90/180/365天。
- 特征可见性：`available_at <= issue-24h`。
- 近期30天地点窗：`(issue-30d, issue-24h]`。
- 内层拟合标签：`fit_issue+horizon <= inner_start-30d`。
- 内层评分窗：`issue+horizon <= inner_end`。
- 主暴露样本：按起报时间从早到晚贪心保留，下一起报必须满足
  `T_next >= T_previous+horizon+30d`。
- 四个开发折的预测必须先封存，然后才读取该折目标评分。

## 样本水位和稀疏回退

每个完整5年内层在7/30/90/180/365天下分别约有44/29/14/8/4个非重叠成熟暴露；第三块
因右端预留30天，约为43/28/14/8/4个。完整的逐块M5–6、M6+事件和固定锚点水位已写入
`configs/multitask_s1_development_contract.yaml`。

主要风险是M6+ 7天很稀疏：2015外折的I3为0个M6+事件/0个锚点。这是真实的零事件块，
不是缺失：

1. 对零事件也有定义的计数对数分数/Brier等proper score仍保留该块；
2. 需要正事件才有定义的召回等指标记为 `NA`，不得写成0；
3. 任务/预测时长少于2个成熟内层块时，禁止独立选参；
4. 事件依赖指标少于2个有正锚点块时，回退到预登记proper score或更充足任务的共享参数；
5. M6+ 7天不允许单独选超参数，不得为获得正事件而移动或并合时间块。

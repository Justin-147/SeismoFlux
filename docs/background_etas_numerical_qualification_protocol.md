# ETAS 最小数值资格协议

状态：`Q0 / preregistered_target_blind`

本协议服从 `SEISMOFLUX_IMPLEMENTATION_HANDOFF.md`，只改变 ETAS 数值修复的实施复杂度，不改变科学问题、数据边界、模型、起点、阈值或阶段门控。

## 1. 为什么改线

项目最终要回答的不是“代码能否做得很复杂”，而是：

> 在固定报警面积下，动态异常是否比地震自身产生的 ETAS 背景更能找出未来独立地震区域？

75 km 空间 KDE 已合法通过 G1-LS，证明地震目录具有可复现的空间背景信息。但 ETAS 因一个变换参数端点可能被 `exp(log(bound))` 解码到边界外 1 ULP，目前仍是 `not_evaluable`。没有可评价 ETAS，就无法严谨回答异常是否只是复述余震聚集。

此前 R4/R5 为证明一次数值修复增加了大量 Windows 进程、句柄、运行时依赖和事务证据。两项独立审计确认，这些内容没有改变五个快照、25 个起点、ETAS 目标函数或科学阈值。因此本路线保留必要的科学可追溯性，退出与科学判断无直接关系的复杂实现。

## 2. 唯一近期科学问题

只进行一次有界资格实验：

> 在五个冻结局部支持快照上，使用冻结的 25 个起点和完全相同的 ETAS 定义，端点精确解码后能否得到稳定、可重复的数值解？

唯一允许的总结果是 `evaluable` 或 `not_evaluable`。这不是重新判定 G1-LS，而是判定 ETAS 能否充当阶段4的强制主对照。

## 3. 不变的科学合同

- 快照顺序固定为 `fold_1`、`fold_2`、`fold_3`、`fold_4`、`final_validation`。
- 每个快照只用 `origin_time <= fit_end` 且 `available_at <= fit_end` 的地震历史。
- 五个 `fit_end`、`support_id`、补偿域、公共 `Mc=4.0`、75 km 移民背景 KDE 和三层积分网格全部不变。
- 起点严格取冻结清单中的五快照 × 五起点；不新增、不替换、不因结果改变种子。
- 模型、参数边界、L-BFGS-B 选项和全部资格阈值等于 R4。
- fold 1 和 fold 3 必须报告纳入与排除合格 `unsupported` 父历史的敏感性。
- 该敏感性只在主拟合选中参数处重算排除父历史后的拟合目标，不新增优化调用，也不改变资格结论；若主拟合没有可用参数，明确登记 `not_computable_primary_parameters_absent`。
- 冻结支持清单是权威边界：空间 `raw Mc > 4` 只把该固定格标为 `unsupported`，不得扩散到其他格；不存在合格时间完整度层仍是全实验硬失败；Q2 重建结果必须与清单逐项相等，不能重估或放宽。
- 不读取异常特征、阶段4正式目标、既有分数或锁定测试。
- 不计算信息增益、命中、召回或模型选择。

## 4. 唯一代码修复

只允许修改 `ETASParameterBounds.from_transformed`：

1. 先严格拒绝变换空间冻结边界外的值；
2. 对有限域内值执行原有指数解码；
3. 若变换坐标恰好等于冻结端点，则精确返回对应物理端点；
4. 最后继续执行原有物理边界校验。

禁止使用容差、`clip`、扩大边界或 `nextafter` 放宽输入域，也禁止改变目标函数、优化器、起点或阈值。

## 5. 三个小阶段

### Q0：协议冻结

新增最小配置、协议、验收记录和协议测试。测试、验收、提交、推送并创建 annotated tag 后才进入 Q1。

### Q1：代码冻结

仅加入端点修复、小型 fit-only 运行器、独立复算入口及必要测试。运行全部非锁定测试；提交、推送并创建代码 tag 后才允许接触真实阶段2拟合输入。

### Q2：单次资格

在干净、已推送且与代码 tag 一致的工作树中运行五快照 × 五起点。主运行保存 25 行原始诊断和五个快照门控；随后由独立 `verify` 调用从冻结输入和终点重算 objective、梯度、Hessian、分枝比及三网格指标。

无论结果正负，都必须生成结果清单、验证清单、中文报告、静态 SVG 和离线交互 HTML，完成测试、验收、提交、推送并创建同一个结果 tag。

## 6. 资源与中断

- 一个工作进程、BLAS 单线程，至少保留两个物理核心。
- 启动前若系统 CPU 使用率达到 70%，等待而不抢占用户任务。
- 当前 SciPy L-BFGS-B 路径是 CPU 求解；GPU 可用但不会为这一步带来实质收益。
- 每个快照由一次 `fit_etas` 调用生成五个起点结果，并作为一个 JSON 原子落盘。若进程在该文件形成前中断，内存中的部分优化不构成已完成科学结果；恢复时只允许用完全相同的输入哈希和五个起点重做这个缺失快照。已落盘快照不得替换。
- 结果清单公开每个起点的初始与终止变换向量、解码参数、objective 和 gradient，但不公开事件身份或坐标；独立复算因此无需信任主运行汇总值。

## 7. 判定与停止

每个快照必须同时满足配置中的收敛起点数、梯度、best-three 一致性、Hessian、分枝比和三网格阈值；五个快照全过才是 `evaluable`。Hessian 固定使用变换尺度目标函数的中心二阶差分，步长为 `1e-4 × max(1, |parameter|)`，结果对称化；边界 stencil 非法时直接失败，不改用单边替代。

- `evaluable`：冻结五套参数，完成同支持域 uniform/KDE/ETAS 接口，然后在任何正式目标读取前发布新的阶段4目标盲执行修订。
- `not_evaluable`：发布可信的数值不足结论，保留 KDE 作为当前非异常背景，不读阶段4目标，不再生成 Candidate 8，不进入深度模型或锁定测试。

可信负结果是科学产出；本路线不承诺 ETAS 一定成功，只承诺用一次有界实验结束长期悬而未决的判断。
